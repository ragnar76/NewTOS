# A69 — 3D-Befoerderung G_TEXT → G_BOXTEXT ignoriert das `MD_REPLACE`-Gatter

Status: **ERLEDIGT (2026-09-20) — Pi-Sichtabnahme offen** · Prioritaet: **P3** · Typ: Belegter Defekt / Nebenbefund A67

Abhaengigkeiten: [A67](A67.md)

## Sachverhalt

EmuTOS befoerdert einen hohlweissen G_TEXT/G_FTEXT unter 3D nur, wenn der
Textmodus `MD_REPLACE` ist (`aes/gemoblib.c:586`); ein TRANSPARENT-Text bleibt
Text ohne Fuellung. `object.rs` (Textzweig, hohlweisser 3D-Zweig) befoerdert
und fuellt unabhaengig vom Modus — ein transparenter Text ueber einem
Hintergrundmuster bekommt bei uns eine Flaeche.

## Arbeit

Gatter auf `tmode == MD_REPLACE` nachziehen (`gr_crack` liefert `_mode`
bereits); Hosttest: TRANSPARENT-G_TEXT unter FL3DBAK ueber gemustertem
Grund → Grund bleibt sichtbar.

## Abschluss (2026-09-20)

Ueberschreibung hohlweiss → `backgrcol` bleibt unbedingt (`gemoblib.c:582-585`),
die Befoerderung `G_TEXT→G_BOXTEXT`/`G_FTEXT→G_FBOXTEXT` mit `th = 0` nur bei
`MD_REPLACE` (`:586-599`, `gr_crack`s Bit 7). TRANSPARENT-`G_TEXT` bleibt
ungeboxt, TRANSPARENT-`G_BOXTEXT` wird `backgrcol` gefuellt und behaelt den
Rand. Hosttests rot-vor/gruen-nach (Glyph ueber Schiefer, Grund bleibt),
`xtask test` 680 → 688/0/1, rpi4 64/94; TeraDesks „Disk Volume Information“
(FL3DBAK-`G_FTEXT`, TRANSPARENT) in QEMU vorher/nachher 0 Pixel — erwartet,
Beschriftung auf `backgrcol`-Tafel. Kein Commit (Lead). Belege:
[`A69-STATUS-DONE.MD`](A69-STATUS-DONE.MD), `measurements/measurement-2026-09-20-a68-a70/`.
**Offen:** Sichtabnahme auf der Pi 4.
