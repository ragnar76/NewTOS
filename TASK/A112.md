# A112 — Sieht `evnt_multi(MU_MESAG)` eine an sich selbst gesendete Nachricht?

Status: **OFFEN (Frage)** · Prioritaet: **P2** · Typ: moeglicher AES-Defekt — Nebenfund A25 (2026-10-17)

## Beobachtung

Die A25-Sonde (`sdk/examples/a25reinit.c`) schickte per `appl_write` 16 Byte
an die eigene ap_id und wartete dann mit
`evnt_multi(MU_MESAG|MU_TIMER, 1000 ms)`. Ergebnis in allen memprot-Modi:
`events=32` — nur der Timer, keine Nachricht. Auch ohne zweiten `appl_init`.
Ein `appl_read` derselben Nachricht gelang dagegen
(`measurements/measurement-2026-10-17-a25/`, Logs der frueheren
Sondenfassungen und Kontrolle `ctl2-on`).

Ob das ein Defekt ist, ist **nicht** belegt — es kann ein Sondenfehler sein.

## Auftrag

1. EmuTOS: Pfad `appl_write` an die eigene PD → Nachrichtenschlange →
   `evnt_multi`/`ev_multi` mit `MU_MESAG` (`aes/gemaplib.c`, `aes/gemevlib.c`,
   `aes/gemasync.c`, `aes/gemqueue.c` o. ae.) lesen: wird eine bereits
   liegende Nachricht beim Eintritt sofort erkannt?
2. NewTOS gegenueberstellen (`tos-api/src/aes/`), Datei:Zeile beider Seiten.
3. Mit einer minimalen Sonde in QEMU reproduzieren oder widerlegen (auch:
   Nachricht von einem anderen Prozess, z. B. Accessory → Programm).
4. Falls Defekt: Ursache, Fix-Vorschlag, Test rot/gruen. Breitenwirkung
   pruefen — jede GEM-Anwendung lebt von `MU_MESAG`.
