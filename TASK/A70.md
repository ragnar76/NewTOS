# A70 — FL3DBAK-G_BUTTON bekommt die 3D-Flaechenfarbe, EmuTOS laesst ihn hohlweiss

Status: **ERLEDIGT (2026-09-20) — Pi-Sichtabnahme offen** · Prioritaet: **P3** · Typ: Belegter Defekt / Nebenbefund A67

Abhaengigkeiten: [A67](A67.md)

## Sachverhalt

Die allgemeine Ueberschreibung „hohlweisser Kasten/Knopf nimmt unter 3D die
Flaechenfarbe" in `object.rs` (Kastenzweig) greift bei uns fuer jede 3D-Art.
EmuTOS `just_draw` (`aes/gemoblib.c:646-656`) tut das nur fuer FL3DOBJ
(Indikator/Aktivator); ein G_BUTTON mit FL3DBAK bleibt hohlweiss.

## Arbeit

Ueberschreibung auf `d3obj` einengen; Hosttest FL3DBAK-G_BUTTON → weiss.
Pruefen, welche Dialoge (desk/, form_alert, fsel) FL3DBAK-Knoepfe tragen —
sichtbare Aenderung benennen.

## Abschluss (2026-09-20)

Ueberschreibung fuer `G_BUTTON` auf `d3obj` eingeengt (FL3DIND/FL3DACT →
`indbutcol`/`actbutcol`, sonst hohlweiss; `gemoblib.c:639-658`, D-103);
`G_BOX`/`G_IBOX`/`G_BOXCHAR` behalten FL3DBAK → `backgrcol` (`:619-636`).
Dialogpruefung: `form_alert`/`fsel` FL3DACT, desk/ ohne 3D-Flags, TeraDesk
`desktop.rsc` 0 FL3DBAK-Knoepfe — **keine sichtbare Aenderung heute**, QEMU
vorher/nachher 0 Pixel. Hosttests rot-vor/gruen-nach, `xtask test`
680 → 688/0/1, rpi4 64/94. SELECTED-XOR unberuehrt (A85). Kein Commit (Lead).
Belege: [`A70-STATUS-DONE.MD`](A70-STATUS-DONE.MD),
`measurements/measurement-2026-09-20-a68-a70/`. **Offen:** Sichtabnahme auf der Pi 4.
