# FS13 — `Fclose` nach `Fforce(n,-1)` liefert -65

Status: **OFFEN** · Prioritaet: **P3** · Typ: Konformitaet — Nebenfund LIBC-FSTAT (2026-10-17)

Elternprozess: `fh = Fcreate(…)`, `Fforce(1, fh)`, Kind starten,
`Fforce(1, -1)`, dann `Fclose(fh)` → -65 (EINTRN). Laut
`docs/api/gemdos/file/3e-fclose.md` ist das das zweite Schliessen eines
geteilten OFD. Pruefen gegen EmuTOS (`ixforce`, `xclose`, Referenzzaehlung
des OFD): darf `Fclose(fh)` dort 0 liefern? Der Dateiinhalt ist korrekt.
