# A88 — `menu_popup`: `BEG_MCTRL`-Klammer, `mn_keystate`, `clamp_ypos`

Status: **OFFEN** · Prioritaet: **P3** · Typ: Konformitaet / Nebenbefund A73 (Auditor)

Abhaengigkeiten: [A73](A73.md) (Punkt 3: zweite Loslass-Wartung)

## Sachverhalt

Drei Nachbarn in `tos-api/src/aes/menu.rs` (`menu_popup` `:980-1019`,
`popup_track` `:1027-1081`) gegen EmuTOS `mn_popup`
(`references/emutos/aes/gemmnext.c:304-356`):

1. Keine `wm_update(BEG_MCTRL)`/`END_MCTRL`-Klammer (`:312,353` → `fm_own`,
   `gemfmlib.c:82-107`: Update-Semaphor, `gl_mntree = NULL`, Kontrollrechteck
   = ganzer Schirm, `set_mown(rlr)`). Ohne sie kann waehrend eines Popups die
   Menueleiste einen Track starten.
2. `mn_keystate = 0` (`:1013`); EmuTOS liefert den Shift-Zustand bei der
   Auswahl (`gemmnext.c:272,342`).
3. Popup-y auf `0..` geklemmt (`:1005`); EmuTOS `clamp_ypos` (`:124-127`)
   haelt den Kasten unter der Menuezeile (`gl_rfull.g_y`) in
   `gl_hchar`-Schritten.

Kein SDK-Aufrufer heute (TeraDesk keiner; QED/cflib faellt auf den eigenen
Tracker zurueck, weil `appl_getinfo(9)` bei `AES_VERSION 0x0340` nicht
befragt wird) — Wirkung fuer Fremd-Apps (Lattice C, DevPac per EmuTOS-Kommentar
`gemmnext.c:24-27`).

## Arbeit
