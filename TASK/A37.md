# A37 — fix_tedinfo_std fehlt: te_txtlen wird nicht neu berechnet

Status: **OFFEN** · Prioritaet: **P1** · Typ: Belegter Defekt / SPEICHERFEHLER

Abhaengigkeiten: —

## Herkunft

Befund **B5** des RSC-/`appl_init`-Audits vom 2026-09-11.
**Die vollstaendige Herleitung mit `Datei:Zeile` auf beiden Seiten, Messwerten
und getriebenen Testfaellen steht im Bericht** und wird hier nicht verdoppelt:
[docs/analysis/audit-applinit-rsrc-load-2026-09-11.md](../docs/analysis/audit-applinit-rsrc-load-2026-09-11.md), Abschnitt B5.

Uebersicht aller Befunde: [RSC-AUDIT-INDEX.md](RSC-AUDIT-INDEX.md).

## Der Kern — das ist ein Schreibzugriff ueber einen Puffer hinaus

EmuTOS rechnet nach dem Relokieren nach (`aes/gemrslib.c:655-669`):

```c
if (fix_ptr(R_TEPTEXT,  ii)) ted->te_txtlen = strlen(ted->te_ptext)  + 1;
if (fix_ptr(R_TEPTMPLT, ii)) ted->te_tmplen = strlen(ted->te_ptmplt) + 1;
```

Wir tun das **gar nicht**; der Wert aus der Datei bleibt stehen. Gefaehrlich wird
es im Zusammenspiel mit `tools/mkrsc.py`: `intern_str` kopiert nur bis zum ersten
NUL, waehrend eine klassische `.rsc` hinter `te_ptext` volle `te_txtlen` Bytes
reserviert hat. **Der umgewandelte Puffer ist kuerzer als `te_txtlen`** — und
`objc_edit` begrenzt seine Schreibvorgaenge genau an `te_txtlen`.

Gemessen: `gem_fsel.nrsc` **11 von 13** TEDINFOs betroffen, schlimmster Fall
Puffer 1 B gegen `te_txtlen` 39 → 38 B Ueberlauf direkt in die Schablone
desselben Feldes. `desktop.rsc` 6 von 104. `qed.rsc` 0.

**Fehlerfall:** Tippen in ein editierbares Feld eines geladenen `.RSC`
ueberschreibt die im Blob folgenden Zeichenketten — verfaelschte Beschriftungen,
im unguenstigen Fall ein nicht mehr NUL-terminierter Text.

Der AES-Dateiselektor ist **nicht** betroffen, weil `fsel::set_ted` `te_ptext`
auf eigene Kernelpuffer umbiegt und `te_txtlen = cap` setzt. Das ist eine
**Umgehung, keine Behebung** — und sie darf nicht als Beleg dienen, dass der
Pfad in Ordnung sei.

## Abnahme

Der rote Test des Berichts (`tedinfo_txtlen_is_recomputed_from_the_text`,
meldet `left: 39  right: 1`) als Ausgangspunkt. Danach pruefen, ob die
`fsel::set_ted`-Umgehung zurueckgebaut werden kann oder bewusst bleibt.
