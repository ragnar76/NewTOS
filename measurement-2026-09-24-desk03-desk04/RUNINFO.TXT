0. The default desktop layout changed — read this first
--------------------------------------------------------
Making `Install devices` / `Remove icon` mean anything required the desktop
icon list to become *state* (`G.g_ahead`) instead of being re-derived from
`Drvmap` on every `app_blddesk`. The list therefore has to be **seeded**, and
the seed is EmuTOS's `build_inf` (`deskapp.c:696-752`), which lays the icons
out differently from the invented rule NewTOS used before:

  before (screendumps of DESK01b, `about-A-idle.png`):
      drives down column 0; Trash at (cols-1, 0), Printer at (cols-1, 1)
      -> Trash and Printer in the TOP-RIGHT corner
  now  (`screendumps/boot-desktop.png`):
      drives fill rows left-to-right (`icon_index % xcnt`, `deskapp.c:719`);
      Trash at (0, ycnt-1) — bottom-LEFT — moved to (xcnt-1, ycnt-1) only if
      the drives already reached that row (`:738-744`); the Printer takes the
      bottom-right only when the Trash did not (`:747-754`).

At 640x480 with one drive: C: at (0,0), Trash at (0,9) = (0,433), Printer at
(6,9) = (546,433). The old layout had no source citation; this one is
`build_inf` line for line. Flagged to the lead as a visible change.


1. Boot, product kernel, base image      (boot-desktop.png, serial/boot-…)
---------------------------------------------------------------------------
  The base image ships a 21-byte `newdesk placeholder\r\n` as NEWDESK.INF.
  EmuTOS decides "is there INF data?" on the signature — `if (inf_data[0] !=
  '#') build_inf(…)` (`deskapp.c:833-834`) — NOT on whether a file exists.
  The first cut of this ticket tested file existence and the desktop came up
  with **no icons at all**; the signature check is in the code because that
  run found the defect (the empty-desktop dump is not kept — it was a
  pre-fix state, not a result).

  boot-desktop.png: `Hard disk` (C) top-left, `Trash` bottom-left,
  `Printer` bottom-right. 0 [EXC]/[PANIC].


2. Menu state — `men_update`'s `ndesk`   (men-*.png, serial/men-serial.log)
---------------------------------------------------------------------------
  method/desk03-menu.actions. Click the C: icon, open Options, dismiss,
  deselect, open Options again.

  men-C-sel.png   (one desktop icon selected):
      Install icon...     black (enabled)
      Install devices     black (enabled)
      Remove desktop icon BLACK (enabled)
  men-E-nosel.png (nothing selected):
      Install icon...     black (enabled)
      Install devices     black (enabled)
      Remove desktop icon GREY  (disabled)

  That is EmuTOS exactly: "disable 'Remove desktop icon' iff no desktop icons
  are selected" (`deskmain.c:540-542`), and neither `IDSKITEM` nor `IICNITEM`
  appears in any `ILL_*` table (`:143-160`) or is disabled by hand. A greyed
  menu entry is the *whole* of EmuTOS's answer to "Remove with nothing
  selected" — there is no alert.

  Note for the next author: the first click after a drop-down is open is
  eaten by the AES menu tracker (it dismisses the menu). The action list
  selects the icon *before* touching the bar for that reason; an earlier
  ordering produced a dump with the icon unselected.

5. The written file                     (inf/NEWDESK.INF.after-install)
---------------------------------------------------------------------------
  Read out of the run's image afterwards:

    #R 02
    #E 1A E0 00 00 60
    #Q 41 40 43 40 43 40
    #W 00 00 00 01 50 1C 00 @     (x7)
    #M 00 00 00 FF C Hard disk@ @
    #T 00 09 03 FF   Trash@ @
    #O 06 09 04 FF   Printer@ @
    #T 01 00 03 FF   @ @
    #F FF 07 @ *.*@   …the eight file-type defaults…

  `#M 00 00 00 FF C` = grid (0,0), a_aicon 00 = IG_HARD, a_dicon FF = NIL,
  letter C. `#T 00 09 03 FF` = grid (0,9), IG_TRASH. `#O 06 09 04 FF` =
  grid (6,9), IG_PRINT. The fourth line is the icon just installed: grid
  (1,0), IG_TRASH, no letter, empty label.

  Two things worth naming. (a) The icon number is now real — before this
  ticket every `#M`/`#T`/`#O` line was written with `FF FF`, because there
  was no per-icon state to write. (b) The `#E`/`#Q` bytes are unchanged from
  `build_inf`'s defaults, so the file a first-ever Save writes is still
  EmuTOS's.

7. The removal has to survive too       (rms-*.png, cold2-desktop.png)
---------------------------------------------------------------------------
  method/desk03-rmsave.actions: select C:, Remove desktop icon, Save desktop.

  inf/NEWDESK.INF.after-remove carries only

    #T 00 09 03 FF   Trash@ @
    #O 06 09 04 FF   Printer@ @

  — no `#M` line. cold2-desktop.png (product kernel, that image): Trash and
  Printer, **no C: icon**. This is the asymmetry the signature check in §1
  buys: a file that *is* INF data and happens to carry no icon line describes
  a desktop with no icons and is honoured; only a missing or unsignatured
  file gets `build_inf`. 0 [EXC]/[PANIC].
