A33 counter-measurement -- wm_delete must arm the slot it frees.

Taken 2026-09-12 after the fix in tos-api/src/aes/window.rs:

  (a) new internal `wm_delete(handle)` (EmuTOS aes/gemwmlib.c:1466-1485):
      close first if VF_ISOPEN, dump the rectangle list (`newrect`), then
      WS_CURR = WS_PREV = gl_rscreen and WS_FULL = WS_WORK = gl_rfull
      (:1477-1480), w_flags = 0 (:1481), w_owner = NULL (:1482).
      `wind_delete` is now that function's opcode; `wm_new` runs EmuTOS'
      loop `if (VF_ISOPEN) wm_close(wh); if (VF_INUSE) wm_delete(wh);`
      (:1886-1890) instead of blanking the table, so a slot that is *not*
      in use is left exactly as it was.
  (b) `wind_create` carries WS_WORK across its slot reset: `wm_create`
      writes WS_CURR, WS_PREV and WS_FULL only (:1377-1379) and `w_setup`
      does not assign w_work (:205-228), so the gl_rfull that (a) leaves
      behind is what the next occupant of the handle reports.
