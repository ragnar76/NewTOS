0. T10 BIT, AND WAS WORKED AROUND (T10 STAYS OPEN)
---------------------------------------------------------------------------
a78_patch2.py's dual arming picks the empty SCRIPT_TERA whenever an EL0
process is the running one at the first injector tick; since the accessories
landed that is always the case, so the run completes and nothing happens on
the screendumps.  That is TASK/T10.md.

method/t10_workaround.py replaces the dual arming, in the scratch copy only,
with the single case this measurement needs: step only once "[desk] desktop
up" has set DESK_UP, always run SCRIPT_DESK.  It is PORT01's workaround under
a new name.  The shared harness (a78_patch2.py) is untouched and T10 stays
OPEN: the other half of its decision -- the TeraDesk-via-#Z runs -- cannot be
re-measured from these four tickets, and a half-verified harness fix is worse
than a named workaround.  A real fix should make the *script* say which
program it means instead of sniffing what happens to run first.

4. DESK31 -- the file-engine remainders
---------------------------------------------------------------------------
item 5 (wording).  d31a: the C: icon dropped on the PRINTER is
`fun_desk2desk`'s "neither disk nor trash" arm -> "Illegal operation!"
(screendumps/d31a-e-prnt.png), the STILLOP text, where it used to say
"Operation not allowed."

item 6 (wants_to_delete_files).  d31a: the C: icon dropped on the TRASH ->
"Do you want to remove icons|or delete files?" with Icons | Files | Cancel
(screendumps/d31a-c-rmvdel.png) -- EmuTOS's STRMVDEL, in its button order,
where NewTOS used to ask its own "Delete the selected item(s)?" with
Cancel | OK.

item 2 (STILLDIR).  d31b: a folder shortcut for C:\SUB on the desktop, then
the SUB folder dragged out of the C:\ window onto it -> destination C:\SUB\SUB
-> "Illegal directory operation!" with Skip | Abort
(screendumps/d31b-e-stilldir.png), over the COPY FILE(S) box.
  NOTE, and it is why the action list looks the way it does: dropping SUB on
  ITSELF cannot reach this alert.  `act_bdown` cancels a drop on the dragged
  item one layer higher ("if ((wh == dst_wh) && (*pdobj == sobj)) dst_wh =
  NIL", deskact.c:666-670) -- the first attempt did exactly nothing, which is
  correct behaviour, not a defect.

item 1 (d_dofileren asks).  Ctrl-drag C:\PROOF.TXT onto the same C:\SUB
shortcut: same drive, so OP_MOVE becomes OP_RENAME, and C:\SUB\PROOF.TXT
already exists.
  d31c -- *Stop*:  screendumps/d31c-e-namecon.png shows the ADCPALER name
          conflict `get_new_name` puts up.  Read back from the card:
          C:\PROOF.TXT 19 bytes "PROOF: C:\ (root)" and C:\SUB\PROOF.TXT 15
          bytes "PROOF: C:\SUB" -- untouched, both of them.
  d31d -- *OK*, name unchanged: `dos_delete(newname)` then the rename.  Read
          back from the card: C:\PROOF.TXT is GONE and C:\SUB\PROOF.TXT is now
          19 bytes "PROOF: C:\ (root)".  That is the whole of deskdir.c:815-819.
  Both read with method/lsimg.py, a plain FAT16 reader, from the raw image.

items 3 + 4 (`desk_verify` in `rebuild_window`, `fun_mark_for_rebld` /
`fun_rebld_marked`) have no picture of their own: they are the bookkeeping
`do_info`'s rename path uses.  d38b exercises `fun_rebld_marked` (the SHOWITEM
loop calls it after every pass) and every window rebuild in every run above
now goes through `desk_verify`.

5. DESK33 -- F1..F20 launch the bound application
---------------------------------------------------------------------------
Fixture: method/seed_d33.sh adds one line to the NEWDESK.INF the desktop's own
`app_save` wrote in the `d33-seed` run:

  #G 06 FF C:\ARGVTEST.NAP@ *.XYZ@ 107 @      (a_funkey = 7, a_flags = APPDIR)

d33 presses F7 with the pointer parked in the bottom-right corner -- no click
anywhere in the run.  serial/d33-serial.log:

  [d33] process_funkey(7) -> C:\ARGVTEST.NAP appdir=true
  ARGVTEST: cmdlin len 0 raw ""
  ARGVTEST: argc 1
  ...
  [d33] process_funkey(6) -> no application holds it

The empty command tail is EmuTOS's: `do_aopen(pa, TRUE, -1, pathname, pfname,
NULL)` with a non-`isparm` application takes neither the `tail` branch nor
`opn_appl` (desksupp.c:975-987).  screendumps/d33-c-f7.png shows the desktop
intact after the child's Pterm; d33-d-f6.png after the unbound key.

7. WHAT ONLY THE REAL PI CAN CONFIRM
---------------------------------------------------------------------------
Every gesture here is driven by the scratch-copy IKBD injector.  Real HID
input -- a real mouse drag, a real F7 on a real keyboard, a real Ctrl-drag --
is real-Pi4 only.  The code path is the same: the injector feeds
`crate::ikbd::feed`, which is where the IKBD driver itself delivers.
