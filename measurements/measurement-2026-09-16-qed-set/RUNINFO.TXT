2  DER BEFUND, AUF DIESEM RECHNER NACHGEMESSEN
--------------------------------------------------------------------------------
src/set.c adressiert dieselben Bits auf zwei Arten:

  byteadressiert  setincl(:161) setexcl(:169) setchg(:177) setin(:185)
                  -> Byte (elt>>3), Maske (0x80 >> (elt&7)).  Breiten- und
                     bytereihenfolgeneutral, deshalb unauffaellig.

  wortadressiert  setfree(:8) setmax(:30) setmin(:47) mit fest verdrahteten
                  32 Bit je *set++ und den Konstanten 0x80000000L/0xFFFFFFFFL;
                  setall(:77) und setnot(:105) schreiben 0xFFFFFFFFL je Wort.

Auf m68k (4-Byte-long, Big-Endian) bezeichnen beide Adressierungen fuer dieselbe
Elementnummer dasselbe Bit. Auf LP64/Little-Endian nicht mehr.

Gemessen mit host/settest (siehe Abschnitt 3):

    sizeof(unsigned long)=8   sizeof(SET)=256   SETSIZE=32   SETMAX=1023
    byte order: little-endian
    adressierbar 128 Byte, Objekt 256 Byte

    setincl(s,0)  -> setmin=24  setmax=24   (m68k: 0 und 0)
    setincl(s,1)  -> setmin=25  setmax=25   (m68k: 1 und 1)
    volle Menge   -> setmax=511 setfree=64  setcard=512 (m68k: 1023/1024/1024)

    Die Schleifenform aus QEDs restore_edit (edit.c:2106-2109)
        max = setmax(chg_links);
        for (link = setmin(chg_links); link <= max; link++)
            if (setin(chg_links, link)) ...
    erreicht ihren Rumpf fuer 0 von 41 Fensterhandles.


3  DER HOSTLAUF  (host/settest, vollstaendige Quelle liegt bei)
--------------------------------------------------------------------------------
Drei Fassungen werden je Testfall verglichen:

  ORAKEL  die reine Definition "Menge von Elementnummern 0..1023" mit der
          Byteabbildung, die setincl/setin ohnehin benutzen
  MODELL  eine woertliche Transliteration von src/set.c mit ausdruecklichen
          32-Bit-Big-Endian-Wortzugriffen (m68kmodel.c) -- das, was die
          unveraenderte Quelle auf m68k TUT
  GERAET  der Pruefling, uebersetzt fuer diesen Wirt (LP64, Little-Endian):
          entweder die unveraenderte src/set.c oder die Overlay-Fassung

ORAKEL gegen MODELL validiert das Modell (0 Abweichungen in allen Laeufen).
MODELL gegen GERAET ist das Urteil.

2856 Testmengen, jede prueft alle 17 Funktionen aus set.h: leere Menge, volle
Menge, jedes einzelne Element 0..1023 als Einermenge, jede volle Menge minus ein
Element, 441 Paare auf einem Raster (Wort- und Byte-Grenzen), 300 Pseudozufalls-
mengen, 64 zusammenhaengende Bereiche, str2set ueber 13 Zeichenketten, dazu eine
Menge mit absichtlich verschmutzter Polsterung.

6  WAS QEMU HIER NICHT ZEIGEN KANN
--------------------------------------------------------------------------------
Der eigentliche Fehler ist in QEMU NICHT ausloesbar. raspi4b meldet
"[pcie] RC not present (no response at RC_BASE); USB disabled" -- es gibt dort
keine Tastatur und keine Maus. Ohne Eingabe wird weder ein Editorfenster
geoeffnet noch eine Taste gedrueckt, also laeuft make_chg/restore_edit nie.

Belegt ist damit nur: QED startet mit der neuen set.c unveraendert und zeichnet
unveraendert. Dass ein getipptes Zeichen erscheint, ist eine VORHERSAGE fuer die
echte Pi 4 (siehe Quittung, Abschnitt "Die drei Vorhersagen").
