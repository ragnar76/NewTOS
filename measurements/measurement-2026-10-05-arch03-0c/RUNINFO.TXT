OBSERVATIONS (not changed)
  * SIMD registers are not preserved across a Pexec/Pterm round trip: the
    parent's v0-v31 come back as the child left them (finish_terminate
    restores GPRs only; saved_fp is used only by the cooperative switch).
    First CRASHTST build printed rc as zeros because clang hoisted put_hex's
    vector constants across the Pexec svc; crashtst.c's put_hex is now
    noinline/volatile. Pre-existing, independent of 0c.
  * The kernel-launch path (desktop #Z / AUTO / boot) enters EL0 with kernel
    values left in x1..x30 (visible in the crash reports: ffff0000... in X3,
    X9, X16...); the Pexec path zeroes them. Pre-existing.
  * A store to user address 0 does not fault: page 0 is mapped UserRwExec.
  * exceptions.rs finish_terminate: the comment calls a UART line between
    restore_boot_ttbr0 and install_ttbr0 LOAD-BEARING (QUIRK-001); the line is
    gone since a3c4329 (0b finding). Left unchanged. Run 1 and 3 drove this
    exact path (child -> EL0 parent with parent_l0_pa != 0) 7 times per board
    on QEMU 11.0.2 without the line: no wedge. Real Pi unconfirmed.

NOT COVERED HERE

  * qemu-virt cannot run a #Z desktop launch (no block device on that board);
    its crash runs use the kernel launcher from the boot path instead.
