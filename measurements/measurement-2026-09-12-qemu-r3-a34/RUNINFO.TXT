The derived rectangle is gone: the answer no longer depends on `kind` or on the
maximum extent, and int_out[1] now agrees.  The remaining three words are NOT
A34's.  EmuTOS answers gl_rfull here because the reset the table declares is
wind_new -> wm_new -> wm_delete, and wm_delete writes
`w_setsize(WS_WORK, w_handle, &gl_rfull)` (aes/gemwmlib.c:1480) into the slot it
frees, which nothing in the create path then overwrites.  NewTOS' wind_delete
and wm_new write no rectangle at all -- they reset the slot to zero.  That is
ticket A33 (wind_delete setzt die Fensterrechtecke nicht zurueck), measured
here for the first time.

Confirmed, not assumed: with a scratch patch that (a) made wm_new write
WS_WORK = gl_rfull for every slot it frees and (b) stopped wind_create's slot
reset from clearing WS_WORK, the host test
tos-api/tests/aes_window_create_work.rs ::
created_after_a_sweep_answers_gl_rfull_like_the_dump (normally #[ignore]d,
blocked on A33) passes with 0,19,640,461.  The patch was reverted by hand
before this run was archived; the file is byte-identical to its pre-experiment
copy.  BOTH halves are needed: A33 alone would stay invisible because
wind_create's `*w = Window::EMPTY` clears the field again.
