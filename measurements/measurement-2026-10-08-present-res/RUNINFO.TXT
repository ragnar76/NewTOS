measurement-2026-10-08-present-res -- PRESENT.NAP slides at 1024x768, 800x600, 1280x720 (+1920x1080 reference)

WHAT/WHY  The Atari meeting projector is VGA-only (HDMI->VGA converter), so the Pi will probably get a
  lower mode. Question: does PRESENT.NAP render all 9 slides of the OFAM deck correctly at lower resolutions?

HOW  Branch main, HEAD caf30d8b, tree clean. QEMU raspi4b (-append serial=on), headless. The framebuffer size is set with
  -global bcm2835-fb.xres=W -global bcm2835-fb.yres=H (device properties of QEMU's bcm2835-fb; default 640x480).
  Serial line "[fb] VideoCore display geometry detected: WxH" confirmed per run (serial/*.log).
  Kernel = scratch copy of main (rsync) + the INPUT01 scratch IKBD injector (method/apply-injector-input01.py,
  method/make-inj-input01.sh, script method/present.actions), board-rpi4 release, own cargo target dir.
  Product code untouched. Card = ONE base image (32 MiB MBR+FAT16, method/seed-present-card.sh) with
  C:\Apps\PRESENT\{PRESENT.NAP,SLIDES.TXT,PI4.PNG,DESKTOP.PNG,ZVIEW.PNG}, SLIDES.TXT = "@spacing 5" + docs/presentation/ofam-2026-slides.txt,
  NEWDESK.INF #Z C:\Apps\PRESENT\PRESENT.NAP@. Per run an APFS clone (cp -c), deleted after the run.
  Per run (method/run-res.sh + drive-m3.py): PRESENT autostarts, the injector presses Right (scancode 4D/CD) 8 times
  and Esc (01/81); a screendump is taken 2.5 s (host) after each "[m3] MARK Sn" (the key follows 5 s later), then
  DESK (after Esc) and end.

RESULT (screendumps/<WxH>/r<WxH>-S1..S9.png = slides 1..9, -DESK = after Esc, -end)
  All four resolutions: 9/9 slides rendered, footer "n / 9" correct, PRESENT exited with rc=0
  ("[shell] sh_ldapp: ... exited with rc=0"), desktop (menu bar, icons, green desktop) back after Esc, no exception
