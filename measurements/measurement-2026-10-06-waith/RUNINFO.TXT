DEFECT (found by VFORKT, ARCH03 stage 2e): mintlib's include/sys/wait.h reads
the status word through struct __wait { junk:16; retcode:8; coredump:1;
termsig:7; } -- big-endian bit-field order. On AArch64 (little-endian,
AAPCS64: first field = least significant bits) retcode lands in bits 16..23,
termsig in 25..31: WEXITSTATUS == 0 and WIFEXITED == 1 for every status word.

SOURCE (mintlib 0.60.1, sdk/libc/mintlib-0.60.1.tar.xz):
  unix/wait4.c        builds *stat_loc by integer arithmetic: low two bytes
                      of Pwaitpid/__waitval swapped -> exit code / stop signal
                      bits 8..15, core bit 7, termsig bits 0..6; no bit-fields.
  unix/wait.c, wait3.c, waitpid.c  call wait4; no bit-fields.
  mintlib/thread.c:146 (overlay)  __waitval = (pid << 16) | Pexec's return.
  include/sys/wait.h  W_EXITCODE(ret,sig) = ret<<8|sig, W_STOPCODE(sig) =
                      sig<<8|0x7f, WCOREFLAG 0x80 -- the same layout.
  Bit-field users in mintlib: sunrpc/key_call.c (union wait .w_retcode),
  sunrpc/rpc_main.c, unix/test-vfork.c, test-skeleton.c -- none built by
  build-libc.sh. tz/private.h defines its own integer WIFEXITED/WEXITSTATUS
  only #ifndef. => only the header needs the fix; the library is layout-correct.
  posix/system.c: POSIX branch returns the waitpid status; TOS branch
  (system_hack) returns spawnvp's raw exit code (not a wait status) --
  mintlib behaviour, unchanged, now documented in docs/sdk/07 §8.
