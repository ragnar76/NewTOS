measurement-2026-10-13-crt0-main -- TASK/LIBC-MAIN: the libc start-up code
sdk/libc/crt0.S calls mintlib's own `_main` (= `__libc_main`,
mintlib/main.c:77-305) again instead of `exit(main(__libc_argc, __libc_argv,
environ))`, for programs and accessories alike, as mintlib's `_crtinit`
(crtinit.c:257) and `_acc_main` (crtinit.c:147) end. Follow-up of TASK/FS10
(f3970e1e), which removed the cause of the first attempt's failure
(measurements/measurement-2026-10-06-post-e9/diag-libc-main/README.TXT: every
stdout write -1/EBADF, because `init_stream_mode` gives the console streams a
seek function and NewTOS answered the first Fseek(0, h, SEEK_CUR) with EIHNDL).

WHAT `_main` DOES BEYOND exit(main()) (mintlib-0.60.1, sdk/libc/mintlib/mintlib/main.c)
  :87      __set_errno(0)
  :95-98   Getcookie(C_MiNT) -> __mint (NewTOS: no MiNT cookie -> 0, TOS path)
  :100-101 _app: Pdomain(1)  (NewTOS: EINVFN, as EmuTOS above MAX_FNCALL,
           references/emutos bdos/bdosmain.c:444-445; result only stored)
  :107-108 Pgeteuid==Pgetuid && Pgetegid==Pgetgid -> not secure (all EINVFN -> equal)
  :115-142 UNIXMODE (b, r<c>) -> __default_mode__, _rootdir
  :147-158 MiNT-only (Dgetdrv for U:) -- skipped, __mint = 0
  :161-162 __open_stat[] = FH_UNKNOWN
  :168-169 !*argv[0] && isatty(2) -> Fforce(2, -1)  (spec docs/api/gemdos/file/46-fforce.md:
           BIOS handle stored as is, E_OK; NewTOS isatty = fds 0..2)
  :191-198 setvbuf stdin _IOFBF / stdout _IOLBF / stderr _IONBF (size 0: EINVAL
           after the mode bits are set -- mintlib's own quirk, identical on TOS)
  :201-203 init_stream_mode: tty under TOS -> text mode, io functions replaced
           (seek function back) -> first flush Fseek(0, h, SEEK_CUR) = 0 since FS10
  :226-291 PATH (or PCONVERT list) in environ -> malloc'ed Unix form
           (_path_dos2unx, unx2dos.c:217): PATH=C:\ -> PATH=/dev/c/; raw p_env untouched
  :294     __set_errno(0)
  :303     exit(main(argc, argv, envp))
  `__main()` (global ctors, crtinit.c:142-145/252-255) exists only under
  __GCC_HAVE_INITFINI_ARRAY_SUPPORT, which clang does not define for
  aarch64-unknown-none-elf (checked with -dM -E): mintlib/__main.c is empty in
  our build, nothing to call.
  Duplication check: newtos-arch/heap_init.c (`__libc_crtinit`) and cmdargs.c do
  _base, parseargs (environ/argv, PATH=\0C:\ join, ARGV= cut), _stksize policy,
  Mshrink / accessory stack, _app, acc argv/environ -- none of the above. No
  overlap; crt0 now passes the same (argc, argv, environ) as before, only to
  `_main` instead of main.
