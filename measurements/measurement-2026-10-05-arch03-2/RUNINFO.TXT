PROBES (method/tests, built by method/build-s2-tests.sh against sdk libc)
  PFLAGS1/2  p_flags read back from the note; TPA/env pool by PF_TTRAMLOAD;
             PFLAGS2 patched with `cargo xtask prgflags ... 0x7`
  P567       Pexec 5 fields, pool, start at p_tbase (x0 = PD, os_run, p_parent),
             4 leaves ownership, 7 flags from path (never read as a string),
             6 gives memory to the child (EIMBA after), EINVFN for mode 8
  TSRPAR/TSRRES/TSRUSE  Ptermres(blkln): resident code/data/BSS/Malloc block
             alive and callable from the parent and from a later program;
             TPA beyond blkln back in the pool (TT largest block 0x3a568ff0
             -> 0x3a566590); Mfree of TSR memory = EIMBA
  OWNPAR/OWNKID  Mfree/Mshrink of a parent block by a Pexec-0 child = EIMBA;
             Pexec 3+4 child co-owns basepage+env and shares the caller's
             memory space; a Pexec-4 thread frees a caller block; freed
             unstarted PD cannot be started
  VFORKT     vfork (child runs first, writes parent memory, _exit(42)),
             waitpid -> pid + status 42<<8, second vfork, ST pool back,
             system() POSIX branch with $SHELL -> status 127<<8 (execve =
             Pexec(200) -> EINVFN, as on EmuTOS), system(NULL) == 1
  Probe corrections (no product change): OWNKID expected a Pexec-4 child to
  stop owning its env after one Mfree -- the spec (E6, FreeMiNT FORK_SHAREVM)
  makes it share the caller's memory space, so the second Mfree frees; VFORKT
  first used mintlib's WEXITSTATUS, which reads big-endian bit-fields and
  returns 0 on AArch64 (header defect of the port, reported, not fixed).
