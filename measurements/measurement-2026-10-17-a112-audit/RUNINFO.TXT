A112 — independent audit of AES event wake-up (evnt_multi and single waits)
============================================================================

         analyses, probes or commit messages (user request: "kein
         Ausgangspunkt"). Question given: do evnt_multi and the single
         event waits wake under the same conditions as EmuTOS, while the
         caller is blocked, with several AES processes present?

Findings (auditor, verbatim substance)
  Core cause: evnt_multi always sleeps on wait_input() whatever the flags
    (tos-api/src/aes/event.rs:717); messages wake only wait_mesg
    (pd.rs:436,461,474-476), timers only CLASS_TIMER keys
    (sched.rs:788-794); a sleeper that is not the spinning process is
    only re-checked on input (sched.rs:545-563,781-784).
    EmuTOS arms each event with iasync (gemevlib.c:231-263); sender wakes
    via aqueue->azombie->signal->drl (gemqueue.c:85-125,
    gemasync.c:35-77); timer via adelay/tchange->evremove
    (geminput.c:496ff, gemflag.c:32-64).
  F1 high, run   MU_TIMER of a blocked non-running evnt_multi never fires.
  F2 high, run   MU_MESAG of a blocked non-running evnt_multi not woken by
                 another process's message.
  F3 medium, run AES calls never yield: EmuTOS super() dsptch()es after
                 every call (gemsuper.c:452-464, gemdisp.c:74-79,180-254);
                 NewTOS aes::dsptch only pumps input (mod.rs:784-792),
                 appl_yield returns 1 (appl.rs:399-401). Side finding:
                 evnt_timer(0) waits >= 1 tick in EmuTOS
                 (geminput.c:500-501), returns at once in NewTOS
                 (event.rs:870-873).
  F4 low, source A resumed evnt_multi re-runs the immediate checks
                 (pass = 0, event.rs:453,585-596,626-629); EmuTOS checks
                 once at arm time (gemevlib.c:184-203, geminput.c:446-483).
  Spec error     docs/api/aes/event.md edge case 2 (~823) says a 0 ms
                 timer fires "immediately without yielding" — wrong on
                 both counts.
  No divergence  single waits evnt_mesag / evnt_timer / appl_read wake
                 correctly from other processes (run2/3/4b); a running or
                 sole evnt_multi gets timer and message (run3 loops 1-7).
  Not reproduced (no input device in QEMU): wake by key/button/rectangle;
                 masking by mouse movement on real hardware.

Result: confirms the A112 defect independently and widens it (F1-F3).
