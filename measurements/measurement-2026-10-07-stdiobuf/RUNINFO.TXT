MEMORY FINDINGS (source + the runs below)
  * Per open FILE: one malloc(32768) at the stream's first transfer (not at
    fopen), freed by fclose (fclose.c:16-18). If malloc fails, init_stream
    halves down to 128 bytes, then runs unbuffered -- no error, no crash.
  * Upper bound: GEMDOS has 16 open files system-wide
    (tos-api/src/bdos/fs/file.rs OPEN_FILES 16) -> stdio buffers <= 512 KiB
    in total, whatever the programs do.
  * Programs: QED options.c opens at most 2..3 config files at once (fd, tf;
    text mode) -> <= 96 KiB transient; its text load/save uses Fopen/Fread
    directly (file.c). TeraDesk's file layer is its own XFILE over
    Fread/Fwrite (xfilesys.c x_fopen) -- stdio only for an optional log
    file; the copy trace is identical before/after (284 cmds, 1713 blocks).
    zView: one stream per picture being decoded (JPG/PNG/GIF codecs) plus
    prefs.c zview.inf; DOOM: one permanent stream (the WAD), 32 KiB of its
    malloc arena (its zone is 6 MiB). WinDom (LDGDEMO) reads its config with
    fopen("r") -> transient 32 KiB.
  * Default malloc of a program/accessory goes to GEMDOS Malloc (_split_mem,
    sdk/libc/newtos-arch/heap_init.c), so the buffer does not come out of a
    small TPA; an accessory's malloc is GEMDOS Malloc too (_acc_main path).
    SYSACC.NAC is built WITHOUT libc (sdk/build.sh: crt0 + app only) --
    unaffected, not rebuilt for the card.
  * LDG modules link libshare's malloc (16 KiB static block, then sbrk ->
    ldg_Malloc in the CALLER's context; an empty hunk is returned with
    ldg_Free, libshare malloc.c:271-289). A codec's fopen happens in
    reader_init, i.e. in zView's context: its 32 KiB is an ldg_Malloc
    (> 16 KiB static block) owned by zView and given back at fclose. The
    module's exit-time streams are the console handles 1/2 -> still 1024
    -> the LDG-M3-B2 scenario (sdk/libshare/tests/libshare-host.sh) is
    unchanged and still passes. zView with BIG.JPG and the 15 samples, and
    LDGDEMO (EX_LIB.NLD + POPUP.NLD) below run identically.
  * Text-mode writes: __stdio_text_write's alloca grows from 1 KiB to 8 KiB
    (capped at 8192); default stack 64 KiB (MINKEEP), zView 512 KiB.
