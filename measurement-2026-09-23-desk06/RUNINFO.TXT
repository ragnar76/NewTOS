0. The one piece of scaffolding that is new, and why
----------------------------------------------------
`method/desk06_patch.py` adds three things to the scratch copy:

  (1) `h02_inject::step()` inside `console_read_key_blocking`'s spin.
      The injector normally only runs from `pump_input`, which is the AES
      event loop's idle pass. While EmuCON blocks in `Cnecin` the AES is not
      running at all, so without this hook no scripted keystroke could ever
      reach the console. It is the QEMU stand-in for a keyboard and changes
      nothing about the product path.
  (2) a serial dump of the File drop-down's entry rectangles, texts,
      `ob_flags` and `ob_state`, so the click point for `Execute EmuCON` is
      measured and the enable/disable state is read off the objects rather
      than off the pixels.
  (3) one serial marker on each side of the nested console pass
      (`[desk06] console: alpha mode entered` / `graphics mode restored`).

4. Control run: those two pixels are not this ticket's
                                          (redraw-*.png, serial/redraw-serial.log)
---------------------------------------------------------------------------
  method/desk06-redraw.actions. **Does not touch `Execute EmuCON`.** It opens
  the `C:\` window and then double-clicks `HELLO.NCP`, i.e. the *pre-existing*
  console-program path (`main::launch_native`, `ftype::Flavor::Console` →
  `fbcon::clear_and_home`, run, `console_pause_for_key`,
  `redraw::redraw_desktop`), which predates DESK06 and ends in the very same
  `redraw_desktop`.

  redraw-B-window.png vs redraw-D-after.png: 1584 differing pixels, of which
  1582 are the selected `HELLO.NCP` icon+label (inverted by the double-click).
  The other two are:
    (593,43)  green -> white
    (48,444)  green -> white
  — **the same two pixels**. So the delta belongs to `redraw_desktop` vs
  `wind_open`'s incremental frame draw (the incremental path leaves two corner
  pixels unwritten), not to `File → Execute EmuCON`. It wants its own ticket.

  A first attempt used `Options → Read .INF file...` instead; it returns early
  on this card image because `load_and_apply()` rejects the 21-byte
  `NEWDESK.INF`, so no redraw ran at all and "0 differing pixels" proved
  nothing. Recorded in the head of the actions file so nobody repeats it.
  0 [EXC]/[PANIC].
