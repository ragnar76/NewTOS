AES round 4 -- the companion list: everything the inventory names that
aes-r4-subfunctions.tsv does NOT measure, by name, with the reason.
Nothing below is an oversight; each line is a decision with a citation.

Legend for the reason column:
  ALERT   the dispatcher's default arm pops fm_show(ALNOFUNC), a modal alert
          around fm_do's while(cont) ev_multi(MU_KEYBD|MU_BUTTON) loop
          (gemsuper.c:411-417, gemfmlib.c:389-400, gemfmalt.c:383,
          gemfmlib.c:300-313).  Unattended = hang.
  GUARD   core/cases.c's aes_opcodes[] refuses the opcode, so the LOADER
          rejects the whole table and nothing runs at all.
  PTR     the arm needs a real pointer in addr_in, which a table that has to
          be byte-identical on two machines cannot carry (core/runner_aes.c
          poisons addr_in with 0xDEAD).
  BLOCK   the call itself waits for the operator.
  FATAL   the call ends, replaces or damages the run.
  DRAW    the effect is pixels, not a return value -- needs a screendump.

1. FREE OPCODE NUMBERS -- 16, 18, 27, 28, 29, 49, 57..69, 83..89, 92..99,
   115..119                                             ALERT + GUARD
   Both, independently.  Verified: casecheck --aes on a one-line probe with
   opcode 16 exits 1, "not an AES opcode: crysbind has no arm for it".
   Opcode 0 is the one exception and IS measured (cases 273, 274, 275).

2. REFUSED BY THE LOADER ALTHOUGH THE MEASURED ROM HAS THEM
   Both machines log ap_version 0340, and config.h:1345-1354 makes 0x0340
   mean CONF_WITH_3D_OBJECTS && CONF_WITH_MENU_EXTENSION &&
   CONF_WITH_WINDOW_COLOURS && CONF_WITH_GRAF_MOUSE_EXTENSION.  The guard's
   GATED reason names TOS 3.06 / AES 3.20, which is not what was measured.

                                 INDBUTCOL, ACTBUTCOL, BACKGRCOL, AD3DVALUE,
                                 each get and set bar the AD3DVALUE set arm)
                                 plus 2 fallback classes.  The largest single
                                 hole in the table.
   17  appl_yield         GUARD  dsptch(), no parameters, provably harmless.
   82  scrp_clear         GUARD  (and FATAL: it deletes files.)
  126  shel_rdef          GUARD  (and PTR.)
  127  shel_wdef          GUARD  (and PTR.)
   36  menu_popup         GUARD  (and BLOCK, and PTR.)
   37  menu_attach        GUARD  (and PTR.)  3 ME_* values + 1 fallback

3. REFUSED AT OPCODE GRANULARITY, THOUGH ONE ARM IS PROVABLY NON-BLOCKING
   25  evnt_multi         GUARD  MU_TIMER with tmcount == 0 takes the "quick

8. WHAT THE DUMPER WOULD NEED TO CLOSE THE BIGGEST HOLES
   a) An addr_in column that names a dumper-owned BUFFER by number, the way
      cases/vdi-raster.tsv already names its two pixel buffers instead of
      their addresses.  That single change would unlock the whole of block 6
      -- the object manager, the menu manager, the scrap manager, rsrc_load
      and with it the 17 real R_* types of rsrc_gaddr/rsrc_saddr.
   b) A resource the dumper loads itself before the run, so section 4 asks
      its questions against a real RSHDR instead of a NULL one.
   c) A per-parameter arm in the refusal guard, so "evnt_multi, but only
      with MU_TIMER and tmcount 0" and "form_error, but only n > 63" can be
      stated.
   d) The guard's version premise corrected from TOS 3.06 / AES 3.20 to the
      profile actually measured (ap_version 0340), which would unlock
      objc_sysvar 48 and appl_yield 17 without any format change.
