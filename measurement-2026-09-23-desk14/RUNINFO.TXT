`method/DESKT14.INF` begins `#R 02`, so it passes the signature check, and
differs from the running desktop in two places that show:

  * `#Q 41 40 43 40 72 40` — the >2-plane desktop byte becomes `0x72`
    (IP_SOLID + VDI colour 2), instead of the default `0x43` (pattern 4,
    green);
  * `#M 00 00` / `#T 02 00` / `#O 04 00` — all three desktop icons in the top
    row, instead of the built-in default layout.

`a-e-applied.png` shows exactly that: solid red background, `Hard disk`,
`Trash` and `Printer` side by side in the top row, the selector gone, the
`Options` title back to normal, no alert. The card's own `NEWDESK.INF` is
untouched (the read file is applied, not copied).

NOTE — this is the deviation, not a finding: EmuTOS would have restarted the
desktop here (`deskmain.c:919-925`, `:2136-2148`). NewTOS re-applies in the
running desktop. Lead decision of 2026-09-23, TASK/DESK14.md.


3. `#` alone is no longer enough                   (run B pass 1, run-b.img)
------------------------------------------------------------------------------
    screendumps/b-c-fsel.png            BADSIG.INF in the list
    screendumps/b-d-picked.png          BADSIG.INF selected
    screendumps/b-e-alert-badsig.png    [1][Illegal .INF file format.][ OK ]
    screendumps/b-f-dismissed.png       desktop unchanged afterwards

`method/BADSIG.INF` is

    #Z 00 C:\AUTO\HELLO.NCP@
    #E 1A E0 00 00 60

i.e. it **does** start with `#`, so the pre-DESK14 check accepted it. EmuTOS
requires `#R` or `#E` as the first two characters (`deskapp.c:1523-1525`), and
the new `is_inf_signature` does the same: `STINVINF` (`desk_rsc.c:2560`).
This is the direct evidence for point 2 — a file the old rule would have
swallowed.

`b-f-dismissed.png` (Return = the DEFAULT button) shows the desktop
untouched: background, icon positions and the menu bar are exactly the
pre-alert picture. A rejected file changes nothing.

The standard card ships `C:\NEWDESK.INF` = `newdesk placeholder\r\n`
(`tools/make-sd-image.sh:54`). Before DESK14, `Read .INF file` on that card
was a **silent no-op** — the control run DESK06 lost. It now answers
`STINVINF`. Same card, same run, second pass, so the two passes also prove the
menu item is re-usable and the screen restores between them.

Typing a name that does not exist would be the more natural way to reach this
arm; the injector does not type into fields, so the run reaches it through
the pre-filled default instead. Typing it is HW checklist item 41.4.
