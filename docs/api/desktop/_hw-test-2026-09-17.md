# Hardwareprüfung 2026-09-17 — was auf der echten Pi 4 zu prüfen ist

Neunundzwanzig Prüfungen aus achtundzwanzig erledigten Paketen. **Geordnet nach Wert**: die ersten
zwei entscheiden am meisten, die letzte ist reine Bestätigung.

Jede hat ein **erwartetes** Ergebnis. Weicht etwas ab, ist das ein Befund —
notieren, nicht deuten. Ein Foto ist mehr wert als eine Beschreibung.

## 3. Laufwerksinformation zeigt sinnvolle Zahlen (T01)

**So hinkommen:** TeraDesk → Laufwerkssymbol `C:` wählen → *File → Show info*.

**Erwartet** — vier Invarianten, alle am Bildschirm nachrechenbar:
- Clustergröße ist eine **Zweierpotenz** (Bytes/Sektor × Sektoren/Cluster)
- Gesamtgröße entspricht ungefähr der Partitionsgröße (~477 MB)
- frei ≤ gesamt, und **gesamt − frei = belegt** auf das Byte
- gesamt ÷ Clustergröße ist **ganzzahlig**

*Vorher:* 15-stellige oder schlicht zufällige Zahlen — zwei der vier Felder
waren uninitialisierter Stapelinhalt.

## 30. VideoCore-Alpha-Modus „ignored" im Allokations-Telegramm (nachgetragen 21.09.)

Seit V11/V12 traegt das oberste Byte jedes 32-bpp-Pixels das VDI-Overlay-Bit
(gezeichnet `0x00`, geloescht/komplementiert `0xFF`, vorher ueberall `0xFF`).
Damit das Display dieses Byte nicht als Alpha liest, sendet der Kernel jetzt
set alpha mode `0x0004_8007` = 2 („alpha channel ignored") vor `allocate` und
fragt get alpha mode `0x0004_0007` zurueck (`docs/hardware/mailbox-
framebuffer.md` § 3c). Kernel im Seriell-Log ansehen; Desktop booten; einen
Menuetitel anfahren (invertiert); TeraDesk starten (Bildschirm wird per
`v_clrwk` geloescht = X-Byte `0xFF`).

**Erwartet:** Serial `[fb] alpha mode = 2` (ohne Zusatz in Klammern — die
Firmware hat das Set-Tag beantwortet und 2 echot; QEMU raspi4b: genau diese
Zeile). Desktop in normalen Farben, der invertierte Menuetitel schwarz mit
weisser Schrift, die per `v_clrwk` geloeschte Flaeche beim TeraDesk-Start
weiss — alles wie vor dem Tag. Steht in Klammern `set tag echoed N` oder
`unanswered`, ist das der Befund (Firmware hat den Modus nicht angenommen);
das Bild ist dann trotzdem der Massstab.

## 36. Dateioperationen nach dem Umbau auf den Trap — DESK10 (nachgetragen 23.09.)

Am Kernel-Desktop (ohne TeraDesk). Seit DESK10 geht **jeder** Zugriff des
Desktops auf das Dateisystem und auf die Laufwerksliste ueber den echten Trap
(`svc #1` GEMDOS, `svc #13` BIOS) — vorher war es ein gewoehnlicher
Rust-Funktionsaufruf. Der Punkt prueft, dass dabei nichts verlorenging.

**Zu pruefen, der Reihe nach.**

1. **Laufwerksbuchstaben.** Beim Hochfahren zeigt der Schirm **alle** Platten
   der Karte als Symbole (auf der echten Karte `C:` bis `F:`), und die
   Bootzeile meldet dieselbe Anzahl (`[desk] desktop up (N drives, ...)`).
   Das ist `Drvmap` ueber `svc #13`.
2. **Verzeichnisliste.** Ein Laufwerkssymbol doppelklicken: das Fenster fuellt
   sich mit Namen, Groessen und Datum, die Kopfzeile nennt Byte- und
   Dateizahl. Das ist `Fsfirst`/`Fsnext` ueber den Trap. Ein Ordner darin
   oeffnen und wieder zurueck.
3. **`File → New folder...`**, Name eingeben, `OK`: der Ordner erscheint im
   Fenster (`Dcreate`).
4. **`File → Show info...`** auf einer Datei, den Namen aendern, `OK`: die
   Datei traegt den neuen Namen (`Frename`).
5. **Loeschen.** Den eben angelegten Ordner auswaehlen und `File → Delete`,
   Rueckfrage bestaetigen: er verschwindet (`Ddelete`, bei Inhalt vorher
   `Fdelete`).
6. **`File → Set file mask...`** auf `*.NCP` setzen: das Fenster zeigt nur
   noch `.NCP`-Dateien und die Ordner; zurueck auf `*.*`.
7. **`Options → Save desktop...`**, dann **kalt** neu starten: der Stand kommt
   wieder (`NEWDESK.INF` ueber `Fcreate`/`Fwrite`/`Fclose` geschrieben und
   ueber `Fopen`/`Fread` gelesen).

**Erwartet:** genau das Verhalten von vor DESK10 — der Umbau ist reines
Umverdrahten, kein Verhalten aendert sich. Nach dem Lauf die Karte am Rechner
pruefen (`fsck_msdos`): keine Beanstandung.

**In QEMU raspi4b belegt** (`measurement-2026-09-23-desk10/`): Startbild und
Startprotokoll **bytegleich** vor/nach dem Umbau; der Lauf mit zwei aus
`NEWDESK.INF` wiederhergestellten Fenstern (26 bzw. 1 Eintrag) ebenso; die von
`Save desktop` geschriebene `NEWDESK.INF` **bytegleich** (SHA-256 gleich); der
Dateioperationslauf (`Dcreate`, `Fcreate`+`Fwrite`, Kopie mit `Fdatime`,
`Frename`, rekursives Loeschen, Zaehllauf) 12 von 12 bestanden vor **und**
nach dem Umbau, mit gleicher Ausgabe und **bytegleichem Kartenabbild**;
`fsck_msdos` ohne Beanstandung. Auf der Pi 4 offen — dort sind es **vier**
Laufwerke statt einem, und das ist der Teil, den QEMU nicht zeigt.

## 38. Symbole einrichten und entfernen — DESK03/DESK04 (nachgetragen 24.09.)

Die Pi 4 hat **vier** Laufwerke (`C:`–`F:`), QEMU eines — genau daran haengt
dieser Punkt.

0. **Das Startbild hat sich geaendert.** Die Vorgabeanordnung ist jetzt
   EmuTOS' `build_inf` (`deskapp.c:715-754`): Laufwerke fuellen die Reihen
   von links nach rechts, der **Papierkorb steht unten links**, der Drucker
   unten rechts. Vorher standen Papierkorb und Drucker oben rechts. Erste
   Probe: nach einem Kaltstart **ohne** `NEWDESK.INF` (oder mit einer, die
   nicht mit `#` beginnt) stehen `C:` `D:` `E:` `F:` nebeneinander in der
   obersten Reihe, Papierkorb unten links, Drucker unten rechts.

1. **Menuezustand.** Ohne Auswahl `Options` aufklappen: `Remove desktop icon`
   ist **grau**, `Install icon...` und `Install devices` sind schwarz. Ein
   Laufwerkssymbol anklicken, `Options` erneut aufklappen: `Remove desktop
   icon` ist jetzt **schwarz**. (Achtung beim Nachstellen: der erste Klick
   nach einem offenen Menue schliesst nur das Menue.)

2. **Entfernen.** `D:` auswaehlen, `Options → Remove desktop icon`: das
   Symbol verschwindet, die uebrigen drei und Papierkorb/Drucker bleiben
   unveraendert stehen, kein Rest auf dem Schirm.

3. **Geraete einrichten.** `Options → Install devices`: `D:` kommt an der
   **ersten freien** Rasterstelle zurueck — nicht unbedingt dort, wo es war,
   sondern dort, wo `ins_posdisk` von (0,0) aus zuerst Platz findet. Mehrere
   Symbole entfernen und den Punkt einmal aufrufen: **alle** fehlenden kommen
   in einem Zug zurueck, die vorhandenen werden nicht angefasst (Position und
   Beschriftung bleiben).

4. **Symbol einrichten, neu.** Ohne Auswahl `Options → Install icon...`: der
   Kasten `INSTALL DESKTOP ICON` steht mittig, `Drive` ist vorgewaehlt, das
   Bild zeigt die Festplatte. Die beiden Pfeiltasten durchlaufen
   **Festplatte → Ordner → Papierkorb → Drucker → Programm → Dokument** und
   bleiben an beiden Enden stehen (kein Umlauf). **Die Diskette fehlt
   absichtlich**, solange die Karte kein `A:`/`B:` meldet.

5. **Die Laufwerkskennung.** `Drive` gewaehlt lassen, nichts eintippen, `OK`:
   es kommt `[No drive identifier.][ Retry ]`, der Dialog steht danach wieder

8. **Mehrfachauswahl.** Zwei Laufwerkssymbole auswaehlen, `Install icon...`:

**Erwartet:** vier Laufwerkssymbole beim Erststart, jede der drei Menuezeilen
tut, was sie sagt, und nichts davon ueberlebt einen Kaltstart, das nicht
gespeichert wurde.

**In QEMU raspi4b belegt** (`measurement-2026-09-24-desk03-desk04/`):
