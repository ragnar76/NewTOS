DESK08 + DESK09 -- one package: the two structural gaps every later desktop dialog
depends on (G7 and G2 of docs/analysis/desk-aes-gaps-2026-09-14.md).

  DESK08 (kernel/src/desk/{mod,inf,dir,dlg,insapp,main,redraw}.rs): kernel/src/desk/
    showed its dialogs without `form_center` and without `form_dial`. The three shared
    primitives now sit where EmuTOS has them -- `inf::start_dialog` / `end_dialog` /
    `inf_show` (desk/deskinf.c:349-402) and `dir::draw_dial` (deskdir.c:79-85) -- and all
    four dialog builders go through them: the tree is built at the ORIGIN, `form_center`
    (54) writes the ROOT's position, `form_dial(FMD_START)` (51) reserves, `objc_draw`
    (42) paints INTO THAT RECTANGLE, `form_dial(FMD_FINISH)` (51) gives it back, and
    `end_dialog` drains the messages that queued -- through `main::hndl_msg`, for the
    reason EmuTOS gives verbatim (deskinf.c:371-378). Six `redraw_desktop()` calls behind
    dialogs are gone.
  DESK09 (kernel/src/desk/{global,main,inf,mod}.rs): `G.g_cnxsave` exists as
    `global::CSave` / `WSave` (the full WSAVE field set); `main::cnx_put` / `cnx_get` are
    built 1:1 from deskmain.c:1371-1501, slot order (slot 0 = bottom-most window) and the
    validation against the current `G.g_desk` included. `cnx_get` hangs in the start path
    between `wind_update(BEG_UPDATE)` / `END_UPDATE` (:2053-2057); `cnx_put` at
    `Save desktop` (:891), at the tail of `hndl_msg` on `change` (:1352) and in the
    desktop epilog (:2154).

CORRECTION TO THE TICKET TEXT
  DESK08 says FMD_START/FMD_FINISH "save/restore the background". EmuTOS does not save
  anything: `fm_dial`'s FMD_START arm is a bare `break` with the comment "grab screen sync
  or some other mutual exclusion method" (aes/gemfmlib.c:365-369). The restore is the
  FMD_FINISH REPAINT -- `w_drawdesk(pt)` + `w_update(DESKWH, pt, DESKWH, FALSE)` (:375-379)
  -- which is exactly why `end_dialog` has to drain the message pipe itself. The A57 screen
  buffer is neither needed nor used here.

  1. control (sd-base, stock placeholder NEWDESK.INF, PRODUCT kernel)
     control-desktop.png vs measurement-2026-09-23-a104-a110/screendumps/desk-after-A-idle.png:
     50 px, bbox (319,240)-(640,480) -- the mouse pointer alone (the reference run had parked
     it bottom-right). No regression to the boot picture.

     THE FIRST ATTEMPT AT THIS RUN FAILED, AND IT FOUND SOMETHING. With `window_rect(slot)`
     taken from cs_wnode[slot] unconditionally (EmuTOS' win_alloc, deskwin.c:165), the boot
     window opened at (0,19,640,461) -- the WHOLE desktop. Cause: cnx_get's validation writes
     back into every slot, and an all-zero slot becomes `g_desk.g_w` x `g_desk.g_h`
     (deskmain.c:1476-1483). EmuTOS never sees this because its built-in EMUDESK.INF always
     carries four #W default lines with empty paths (desk_inf_data1, deskapp.c:177-180).
     NewTOS ships none. Resolution (named deviation, in deskmain.md): an unused slot supplies
     no rectangle; the staggered fallback stands. Adopting desk_inf_data1's #W defaults would
     remove the deviation AND change the boot picture (304x192 at (16,96) instead of 544x400
     at (48,43)) -- a decision for the lead, not taken here.

  2. seeded (method/NEWDESK.INF.seeded, PRODUCT kernel) -- cnx_get end to end:
     `#E 9A E0 00 00 60` (VIEWTEXT) + two #W lines, `C:\SUB\*.*` at 04/05/1E/0A cells and
     `C:\*.*` at 18/0F/28/0C.
